# 1️⃣ 데이터 타입

### 📘 01. 데이터 타입의 종류

* 자바스크립트의 타입은 크게 <mark style="color:blue;">`기본형`</mark>과 <mark style="color:blue;">`참조형`</mark> 두 종류로 나뉜다.
* 기본형은 <mark style="color:blue;">`실제 값이 저장된 데이터 영역의 주소`</mark>를 복사하고,\
  참조형은 <mark style="color:blue;">`여러 값이 묶여 있는 객체의 주소`</mark>를 복사한다.

#### ☝️ 기본형 (원시형, Primitive type)

* 숫자(`number`), 문자열(`string`), 불리언(`boolean`), null, undefined, [심볼(`Symbol`)](#user-content-fn-1)[^1]
* 불변성(immutability)을 가짐

#### ✌️ 참조형 (Reference type)

* 객체(`object`)
* 배열(`Array`), 함수(`Function`), 날짜(`Date`), 정규표현식(`RegExp`), [Map, WeakMap, Set, WeakSet](#user-content-fn-2)[^2]이 객체의 하위 분류로 이뤄짐

### 📘 02. 데이터 타입에 관한 배경지식

#### 1️⃣ 비트(bit)와 메모리

* 컴퓨터는 모든 데이터를 0 또는 1로 저장함
* 0 또는 1로 표현할 수 있는 하나의 메모리 조각 → bit
* 비트는 고유한 위치(식별자)를 가짐

#### 2️⃣ 바이트의 등장

* 1바이트 = 8비트 (1바이트 → 2⁸ = **256개 표현 가능**)
*   비트를 묶으면 표현 범위, 검색 효율이 증가하지만 메모리 낭비가 있을 수 있음

    **(표현력 vs 메모리 효율의 트레이드 오프)**

{% hint style="info" %}
### &#x20;언어별 차이

**정적타입 언어**

* C/C++, Java는 메모리 낭비 최소화를 위해 타입별 메모리 크기를 고정함
* 메모리 표현 범위 초과 시 오류 발생
* 개발자가 직접 타입을 변경해야 하는 불편함이 있음 (`short → int`)

`→ 메모리 용량이 부족해서 위와 같은 합리적인 선택을 함`&#x20;



**자바스크립트는?**

* 자바스크립트는 메모리 용량이 커진 상황에서 등장한 언어
* 메모리 효율보다는 개발 편의성에 중점을 둠
* 정수/실수 구분 없이 숫자를 64비트로 저장함


{% endhint %}

#### 3️⃣ 메모리 주소 (<mark style="color:blue;">`= 바이트 단위의 식별자`</mark>)

* 모든 데이터는 바이트 단위의 주소값을 가짐
* 변수는 값을 직접 저장하는게 아니라 메모리 주소를 통해 값을 저장하거나 참조함

{% hint style="info" %}
### &#x20;식별자와 변수

**변수 (variable)**

* 변할 수 있는 수 `→ 변할 수 있는 무언가(데이터)`&#x20;



**식별자(identifier)**

* 어떤 데이터를 식별하는데 사용하는 이름 `→ 변수명`


{% endhint %}

### 📘 03. 변수 선언과 데이터 할당

#### 1️⃣ 변수 선언

```js
var a;
```

* 메모리에서 비어있는 공간을 확보하고, 그 공간에 식별자를 연결하는 것

#### 📌 메모리 상태

| 변수 영역 주소 | 식별자 | 값         |
| -------- | --- | --------- |
| 1003     | a   | undefined |

* 변수 공간이 하나 확보된 상태
* 아직 데이터는 없음 (`undefined`)

→ 선언은 공간 확보 + 이름(식별자) 부여



#### 2️⃣ 데이터 할당

```js
var a = 'abc';
```

* [변수 영역](#user-content-fn-3)[^3]에 a 공간 확보
* 데이터 영역 `'abc'` 저장
* 변수 a에 `'abc'`가 저장된 주소를 기록

#### 📌 메모리 상태

**🔹 변수 영역**

| 변수 영역 주소 | 식별자 | 값(주소) |
| -------- | --- | ----- |
| 1003     | a   | 5004  |

**🔹 데이터 영역**

| 데이터 영역 주소 | 값     |
| --------- | ----- |
| 5004      | 'abc' |

→ 변수에는 직접 값이 저장되는 것이 아니라 값을 저장한 `주소`를 저장



#### 3️⃣ 데이터 재할당 (값 변경)

```js
a = 'abcdef'
```

* 변수 a에 `'abcdef'`를 재할당 하면 `'abc'`에 값을 추가하는게 아니라 `'abcdef'`를 새로 생성함
* 즉, 데이터 영역의 새로운 공간에 값을 새로 저장
* 이후 a가 가리키는 주소를 변경함

#### 📌 메모리 상태

**🔹 변수 영역**

| 변수 영역 주소 | 식별자 | 값(주소) |
| -------- | --- | ----- |
| 1003     | a   | 5005  |

**🔹 데이터 영역**

| 데이터 영역 주소 | 값        |
| --------- | -------- |
| 5004      | 'abc'    |
| 5005      | 'abcdef' |

→ 기존 `'abc'`를 수정하지 않고 새로 생성\
→ `'abc'`에 대한 모든 참조가 끊기면 가비지 컬렉터의 수거 대상이 됨&#x20;



#### 4️⃣ 왜 이렇게 설계했을까?

#### 이유 1) 가변 길이 데이터 처리를 위해

* 문자열은 길이가 계속 변할 수 있음
* 기존 공간을 늘린다면, 뒤에 공간이 없다면 재배치하거나 다른 데이터를 이동해줘야 함 → 비효율
*   그래서 변수 영역과 데이터 영역을 분리함

    → 값은 새로 만들고, 주소만 계속 바꾸는 구조

#### 이유 2) 중복 데이터 처리 효율

```js
var a = 5;
var b = 5;
var c = 5;
```

#### 📌 메모리 상태

**🔹 변수 영역**

| 주소   | 식별자 | 값(주소) |
| ---- | --- | ----- |
| 1001 | a   | 5001  |
| 1002 | b   | 5001  |
| 1003 | c   | 5001  |

**🔹 데이터 영역**

| 주소   | 값 |
| ---- | - |
| 5001 | 5 |

→ 5를 한 번만 저장하고 변수들은 값의 주소만 공유하면 됨 → <mark style="color:blue;">`데이터 영역 메모리 효율 증가`</mark>\
→ 만약 각각 등록한다면 변수영역 3건, 데이터 영역 3건의 대한 메모리가 필요함

### 📘 04. 기본형 데이터와 참조형 데이터

#### 1️⃣ 불변값

*   변수와 상수를 구분하는 성질은 변경 가능성

    → 바꿀 수 있으면 `변수`, 바꿀 수 없으면 `상수`
* 불변값과 상수는 다른 개념\
  → 변수와 상수를 구분 짓는 대상은 **변수 영역 메모리**\
  → 불변성 여부를 구분 짓는 대상은 **데이터 영역 메모리**
* 기본형 데이터는 모두 불변값(숫자, 문자열, boolean, null, undefined, Symbol)

```javascript
var a = 'abc'; 
a = a + 'def'; // 'abc'와 'abcdef'는 별개의 데이터

var b = 5;
var c = 5;
b = 7; // 5를 7로 바꾸는게 아니라 7를 새로 저장
```

* 불변값은 한 번 만든 값을 바꿀 수 없고, 변경은 새로 만드는 동작을 통해서만 이뤄짐
* 한 번 만들어진 값은 가비지 컬렉팅을 당하지 않는 한 영원히 변하지 않음



#### 2️⃣ 참조형 데이터의 할당

* 기본형과 가장 큰 차이점은 객체의 변수(프로퍼티)영역이 별도로 존재한다는 점\
  → 기본형은 주소를 바로 가리키지만, 참조형은 **프로퍼티들의 주소 묶음**을 한 번 더 거쳐감

```javascript
var obj1 = {
  a: 1,
  b: 'bbb'
};
```

**변수영역**

| 주소   | 식별자  | 값(주소) |
| ---- | ---- | ----- |
| 1002 | obj1 | @5001 |

**데이터 영역**

| 주소   | 값                       |
| ---- | ----------------------- |
| 5001 | @7003 \~ ? (프로퍼티 묶음 주소) |
| 5003 | 1                       |
| 5004 | 'bbb'                   |

**객체의 변수 영역**

| 주소   | 식별자 | 값(주소) |
| ---- | --- | ----- |
| 7103 | a   | @5003 |
| 7104 | b   | @5004 |

#### 3️⃣ 참조형 데이터의 재할당 (가변성)

* 객체 내부 프로퍼티를 변경할 때 왜 가변적이라고 할까?\
  → 새로운 객체를 만드는 것이 아니라 기존 객체 내부만 수정했기 때문에 참조형 데이터는 가변적이라고 함

```javascript
obj1.a = 2;
```

**메모리 상태 변화**

1. 데이터 영역에 **`2`**&#xAC00; 없기 때문에 새로운 빈 공간 `@5005`에 `2`를 저장
2. `obj1`이 가리키는 주소(`@5001`)는 그대로
3. 객체 `@5001` 내부의 프로퍼티 `a`의 주소만 `@5003`에서 `@5005`로 변경\
   → 이때 1이 더이상 사용하지않게 되면 가비지 컬렉터의 수거대상이 됨\
   → 가비지 컬렉터는 특정 시점이나 메모리 사용량이 포화 상태에 임박할 때마다 자동으로 수거 대상들을 수거함



#### 4️⃣ 중첩 객체 (Nested Object)

* 중첩 객체는 참조형 데이터의 프로퍼티에 다시 참조형 데이터를 할당하는 것을 말함
* 객체 안에 객체가 있는 경우 참조 체인이 한 단계 더 추가됨

```js
var obj = {
  x: 3,
  arr: [3, 4, 5]
};
```

**메모리 계층 구조**

* 변수 영역: `obj` 주소 저장
* 데이터 영역: `obj`의 프로퍼티 묶음 주소 저장
* obj 프로퍼티 영역: `x`와 `arr` 주소 저장
* arr 프로퍼티 영역: 인덱스 `0, 1, 2`에 해당하는 값들의 주소 저장



#### 5️⃣ 기본형 vs 참조형의 비교 (변수 복사)

* 어떤 데이터 타입이든 변수에 할당하기 위해서는 주솟값을 복사해야 함\
  → 기본형은 주솟값을 복사하는 과정이 한 번만 이뤄지고, 참조형은 한 단계를 더 거치게 되는 차이만 있음

**기본형**

```javascript
var a = 10;
var b = a; // 값 복사
b = 20;    // a는 여전히 10 (불변)
```

**메모리 상태**

* `a`는 여전히 @5001(10)을 `b`는 @5002(20)를 가리킴

**변수 영역**

| 주소   | 식별자 | 값(주소) | 비고                      |
| ---- | --- | ----- | ----------------------- |
| 1001 | a   | @5001 | 초기 할당                   |
| 1002 | b   | @5002 | @5001이었다가 **@5002**로 교체 |

**데이터 영역**

| 주소   | 값  |
| ---- | -- |
| 5001 | 10 |
| 5002 | 20 |

**참조형**

```javascript
var obj1 = { c: 10 };
var obj2 = obj1; // 주소 복사
obj2.c = 20;     // obj1.c도 20으로 변함 (가변)
```

**메모리 상태**

* 내부 프로퍼티를 변경하면 동일한 주소를 공유하던 모든 변수가 영향을 받음
* 참조형도 주솟값을 복사하지만, 그 주소가 가리키는 대상이 객체 내부를 모아둔 변수 영역이기 때문에 내부 요소가 가변적임

**변수영역**

**데이터 영역**

| 주소   | 값                       |

| 5003 | @7001 \~ ? (프로퍼티 묶음 주소) |

| 5005 | 20                      |

#### 6️⃣ 기본형, 참조형 케이스 별 비교

* 값은 재사용하지만 객체 구조는 매번 새로 정의됨

| 구분    | 기본형 (a = 10)  | 참조형 내부 변경  (obj.c = 20) | 참조형 전체 교체  (obj = {c: 20}) |
| ----- | ------------- | ----------------------- | -------------------------- |
| 변동 대상 | 변수 영역의 주소값 변경 | 데이터 영역의 주소값은 그대로        | 변수 영역의 주소값 변경              |
| 특징    | 불변 (새 값 생성)   | 가변 (내부 주소만 교체)          | 불변적 동작 (새 객체 생성)           |
| 재사용   | 값 자체가 재사용됨    | 값은 재사용되나 연결 장부는 새로움     | 값은 재사용되나 객체는 새로움           |
